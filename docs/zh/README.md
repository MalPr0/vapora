## 你为什么可能想要它

**中间没有任何人。** 你的话从你的机器直接到对方的机器。不经过任何公司的服务器，也
不经过我的。没有可以被传唤、被出售、被攻破的"中间"。

**不需要注册。** 没有邮箱、没有手机号、没有用户名、没有资料。程序不知道你是谁，别
人也不知道。

**什么都不保存。** 关掉它，对话就从两端消失了。没有历史记录可以泄露，因为根本没有
历史记录。

**一个文件，零依赖。** 下载一个二进制文件直接运行。不需要 Docker、不需要运行时、不
需要安装。完全用 Go 标准库构建——你可以读到发布出去的每一行代码。

**默认加密，而且无法关闭。** AES-256-GCM，每个方向一把不同的密钥。你分享的那个邀请
**就是**密钥。

**群聊是真正的网状结构。** 每个人都直接和每个人对话。五人房间里的两个人拥有另外三
个人读不到的通道——这不是行为上的承诺，而是算术：他们没有那把密钥。

## 人们用它来做什么

- **给同事发一些敏感的东西**，不必让它永远躺在公司的聊天记录里。
- **穿过防火墙对话**，在你既不能开端口也不能装任何东西的地方。
- **和朋友开一条临时通道**，不留账号、不留历史、两台机器上都不留痕迹。
- **理解你自己的网络**——诊断工具告诉你的，比你的运营商多。

## 两个人

```bash
./vapora punch                 # 你：打印一个邀请
./vapora punch "<邀请>"        # 对方：粘贴并运行
```

**如果连不上，你们各发一个邀请。** 家用路由器通常会拒绝陌生人的数据包，所以当双方
都这样时，各自的第一个包都会死在对方门口。对方的屏幕上会在 *"if it does not
connect, send this back"* 下面打印一行——让对方发给你，粘贴进你的终端，现在你们俩
就在同一时刻敲门了。那正是这些路由器需要看到的。

你可以提前知道自己会不会需要这一步 —— 见[诊断](#先了解你的网络再怪它)。

## 一个群

```bash
./vapora room                  # 开一个房间并打印邀请
./vapora room "<邀请>"         # 任何人都能用它加入
```

**任何人都能邀请。** 五分钟前才加入？`!invite` 会给你一行，用来把下一个人拉进来。
所有人最终都会认识所有人，不用回头去找开房间的那个人。

**邀请你的人不是服务器。** 他介绍两个人认识然后退到一边。他不在两人之间传递任何东
西，就算想读也读不到。关掉开房间的那台机器，对话照样继续。

**房间最多八人**，而且**空了就会关闭**——没人在里面的房间就是一个没有主人的端口。
如果你想让一个房间一直等着，加上 `-standalone`。

**你们两个在同一个 wifi 下？** 那也行。每个参与者会同时公布自己的公网地址和局域网
地址，因为同一个路由器后面的两台机器无法通过公网地址互相到达。几秒钟就会自己解决。

### 在房间里的时候

| | |
|---|---|
| `@名字` | 把你这行从对方的滚动记录里拎出来，并在页边加个标记 |
| `!who` | 谁在这里，以及每条连接的健康状况 |
| `!invite` | 一个新的邀请，用来拉人进来 |
| `!exit` | 离开，并立刻告诉所有人 |
| `PgUp` / `PgDn` | 往回翻看说过的话 |
| `-plain` | 用纯文本行代替全屏界面，出问题的时候用 |

## 它是怎么工作的

你的电脑在互联网上没有自己的地址。地址在你的路由器上，你家里所有设备共用它。这就是
**NAT**，也是没人能直接"呼叫"你笔记本的原因。通常的解法是在中间放一台服务器，双方
都*向外*连到它——这管用，但意味着别人的电脑看得见每一个字。

vapora 做的是另一件事。双方在同一时刻*向外*发包，各自在自己的路由器上打出一个洞，
两个洞对齐。之后这条路径就是直连的，没有别人在上面。

| 是什么 | 为什么在这里 |
|---|---|
| **UDP 打洞** | 直连路径本身。双方同时打洞，在中间相遇。 |
| **STUN** ([5389](https://www.rfc-editor.org/rfc/rfc5389)、[5780](https://www.rfc-editor.org/rfc/rfc5780)) | 弄清外界看到的你的地址，并对路由器的行为分类。 |
| **UPnP-IGD、PCP、NAT-PMP** | 请求路由器开门的三种语言。三种都试，因为路由器很少在说哪一种上达成一致。 |
| **X25519 + HKDF + AES-256-GCM** | 每一对、每个方向都有独立的密钥。在房间里，没有成员能读到另一对的流量。 |
| **抗重放窗口** | IPsec 式的滑动窗口，按发送方区分，让抓到的包无法被重放回来。 |
| **BitTorrent DHT**（可选） | 在完全没有地址的情况下互相找到。默认关闭——见[安全](#安全)。 |

全部来自 Go 标准库。任何地方都没有第三方代码。

## 先了解你的网络，再怪它

```bash
./vapora nat                   # 你在什么样的路由器后面
./vapora diag                  # 你和互联网之间的每一台路由器
```

`nat` 会打印一个像 `CONE-PORT-18` 这样的简短配置码。发给你要连接的人，把对方的填进
来，它会在你**浪费一个晚上之前**告诉你该期待什么：

```bash
./vapora nat -pair CONE-OPEN-64                    # 两个人
./vapora nat -room "CONE-PORT-18,SYM-PORT-F3"      # 整个房间
```

连接能不能成是这一*对*的属性，不是任何一端的——对你自己网络的任何测量都无法单独回答
它。这就是配置码被设计成要粘给别人的原因。对房间来说更进一步：它会说这个网状结构能
不能闭合、谁应该开房间，以及具体哪一对永远到不了对方。

<sup>如果防火墙只开了某一个端口，就测那个：<code>vapora nat -port 41000</code>。过滤是端口的属性，不是机器的。</sup>

## 安全

**邀请就是密钥。** 那串字符不是地址，而是加密一切的秘密。把它当密码对待：任何看到它
的人——截图里、群聊里、从你肩膀后面——都能用它。

**对陌生人保持沉默。** 没有正确密钥的数据包不会得到任何回应。端口扫描器学到的，和扫
一个关闭的端口完全一样。但这些包会被计数，而且**会告诉你**，因为那意味着有人找到了
一个本应只出现在一个邀请里的地址。

**没人能接管你的对话。** 就算你把邀请给了第三个人，他也无法把你朋友挤掉。程序能分辨
他们，会忽略新来的那个，并警告你。

**只有文本能通过。** 其他任何东西都会被丢弃而不是显示。而且来自网络的文本会被剥掉那
些能让人移动你光标、重绘你屏幕或碰到你剪贴板的转义序列。

**邀请在你关掉程序之前一直有效。** 它不会过期，也没有办法吊销。关掉再打开*就是*吊销
——那会给你一把新密钥，通常还有一个新地址。

**在房间里，成员可以谎报还有谁在。** 他可以宣布一个不存在的人。他做不到的是读取或伪
造另外两个人之间说的话。一个编造出来的成员永远不会回应，自己就会掉线。

**"没有账号"不等于隐形。** 和你对话的人看得见你的 IP 地址。这是必然的——数据包从你
家发到他家。这就是*直连*的含义，也是不要服务器所付出的诚实代价。

**`-discover` 会把你的地址公布到一个公开网络上**，所以它默认关闭。开启后，双方通过
BitTorrent DHT 在一个由你的秘密派生出的名字下互相找到。没有那个秘密没人能查到你，但
你确实成了一张任何人都能爬取的表里的一行。

## 什么会坏掉，什么时候

诚实的限制，不是小字条款。

- **那些 STUN 服务器是别人的**——Google、Cloudflare 和另外两家，为别的目的运行的免费
  服务。如果它们消失了，这个程序就无法得知自己的地址，而今天没有备选方案。
- **有些网络会直接封锁它**：公司、大学、酒店、某些移动运营商。你这边做什么都没用。
- **有些连接根本做不到。** *对称型* NAT 或运营商级 NAT 会让你的地址时刻变化，没有可
  以瞄准的东西。`vapora nat` 会告诉你。唯一的解法是中继服务器，而这个程序刻意没有。
- **你的地址一变，邀请就死了。** 换 wifi、切到移动数据、或者闲置得够久。程序会注意到
  并打印一个新的，但你得重新发一次。
- **版本必须一致。** 通信格式已经变过好几次，还会再变。新旧版本无法互通，症状是*一片
  寂静*。请双方先各自运行 `./vapora version`。
- **没有前向保密。** 今天录下你流量、之后又拿到你邀请的人，可以读那段录音。正经的工
  具用"边用边丢"的密钥解决这个问题。这个没有。
- **二进制文件没有签名。** 你的操作系统会警告你，而且它是对的。用 `SHA256SUMS` 校验
  checksum，或者自己编译。
- **`vapora serve` 会改动你路由器的配置。** 它是最早的 UPnP 演示，也是这里唯一一个会
  请求路由器向互联网开端口的命令。它退出时会关掉——但如果崩溃了，那扇门可能一直开到
  路由器重启。这个 README 里其他所有东西都不碰你的路由器。
- **没有以破解软件为生的人审计过这个。** 构建得仔细不等于经过审计。别把重要的东西押
  在上面。

## 你可以怎么用它

<sup>下面链接的 <code>ARCHITECTURE</code> 和 Pong 教程目前只有英文版。</sup>

聊天是建在这个通道上的一样东西，而不是通道的目的。传输层是独立的一层，完全不知道什么
是对话：它穿过两台路由器打开一条加密路径，维持一张网，然后搬运**字节**。

四十行就是一个能跑的程序——它的两个副本，在互联网上任意两台机器上，互相发送字节，中
间什么都没有：

```go
conn, _ := net.ListenUDP("udp4", &net.UDPAddr{})

codec, _ := punch.NewSecretCodec(secret, punch.RoleInviter)
mux := punch.NewMux(conn)
session := punch.NewSession(mux, codec, nil)
mux.Fallback(session)

session.Observe(punch.ObserverFunc(func(payload []byte) {
    fmt.Println("←", string(payload))       // 对方发来的，原样奉还
}))

go mux.Run(ctx)
go session.Run(ctx)

session.Open(ctx, 3*time.Minute)             // 打穿两台路由器
session.Send([]byte("hola"))
```

## 自己编译

对"我该不该信任这个二进制文件"最短的回答：

```bash
git clone https://github.com/MalPr0/vapora && cd vapora
go build ./cmd/vapora
go test ./... -race
```

Go 1.25。没有东西要下载，没有东西要配置。

`pkg/` 里每一个导出的声明都有文档，而且检查工具就在仓库里：
`go run ./internal/doclint pkg`。

**目录结构，如果你想读代码。** `pkg/punch` 是握手、会话和房间。`pkg/stun` 弄清你的地
址并对 NAT 分类。`pkg/upnp` 和 `pkg/pcp` 请求路由器开门。`pkg/dht` 是 BitTorrent 客
户端。`pkg/diag` 是那些建议背后的推理。`internal/tui` 是像素风聊天界面。

[`ARCHITECTURE.md`](../../ARCHITECTURE.md) 是这一切的导览。
[`AGENTS.md`](../../AGENTS.md) 记录了那些不变量——那些看起来像细节、实际上撑着整栋楼的东
西。那份只有英文，因为它是代码的工作参考。
